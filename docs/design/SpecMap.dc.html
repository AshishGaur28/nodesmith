The 13 specifications

Each spec owns one job, one manifest block where it adds a feature, and the diagnostic codes it emits. They stop at generation: the toolchain, and how the generated code must behave. All are drafts.

CORE MODEL
SPEC-00Architecture and IR
Six pipeline stages, atomic emission, and the language-neutral IR with a canonical form and SHA-256 hash. Fixes node numbering and default resolution so equal input gives identical output.
node_ir.schema.json
SPEC-01Manifest schema and syntax
Node, parameters, state, endpoints, services, pipelines and declared message interfaces, plus one block per feature. TOML, YAML and JSON parity, identifier and cross-block rules.
node_manifest.schema.json · ERR_SYN · ERR_SEM
SPEC-02Expression language
Typed statements and expressions, built-in functions, numeric faults, and the exact order in which one pipeline execution evaluates, commits and publishes.
ERR_RUN_101 · ERR_RUN_102
SPEC-03Code synthesis
Turns the IR into rclcpp, rclpy or rclrs packages: type mapping, package layouts, deterministic Jinja2 templates and pinned formatters.
templates/ · runtime library per target
TOOLCHAIN AND RUNTIME
SPEC-04Toolchain and error registry
The nodesmith commands, three validation gates, and the single registry of 46 error codes with exit statuses and text or JSON diagnostics.
validate · lower · generate · bench · clean
SPEC-12Concurrency and state
Callback groups derived from which pipelines share state, so state needs no locks. Parameter snapshot rings, and a run gate for lifecycle transitions.
[concurrency] · ERR_CNC · reference C++ tested under TSan
SPEC-05Lifecycle
Managed-node states, the on_error strategies (TransitionToInactive, Reset, Shutdown), and automatic configure and activate. Pipeline faults and failed transitions take different paths.
[lifecycle] · ERR_LCY
SPEC-07Dynamic parameters
Bounds, allowed values and cross-parameter constraints, enforced as one all-or-nothing batch at runtime and checked against defaults at build time.
parameters.validation · ERR_RUN_103
OPTIONAL FEATURES
SPEC-06Shared memory
Zero-copy loaned messages, C++ only: pool sizing, message types declared fixed-size, and a defined heap fallback when a loan is refused.
[shared_memory] · ERR_SHM
SPEC-08Security
Unsigned SROS 2 governance and permissions derived from the manifest, plus startup checks that refuse to run without the enclave's keys.
[security] · ERR_SEC
SPEC-09Telemetry
LTTng tracepoints compiled out when disabled, a per-callback latency budget in the generated node, and generated benchmark drivers through nodesmith bench.
[telemetry] · ERR_PRF
SPEC-10Real-time
POSIX scheduling policy and priority, memory locking, CPU affinity, executor choice and a deadline per callback group, set up before middleware starts.
[realtime] · ERR_RT
SPEC-11Simulation and fault injection
Follow a simulated clock and inject reproducible faults into a node's own publishers. Refused in release builds unless explicitly allowed.
[simulation] · ERR_SIM
SCOPE AND STATUS
Scope
Software and configuration only. The specs end at the generated source package: no building, packaging or deployment. No hardware, and no ROS interface files: message fields are declared in the manifest. The visual builder in frontend/ has no spec yet.
Verified so far
Cross-references, all 46 error codes, 6 example manifests against the schema, a dry-run front end, and a tested C++ reference for the concurrency primitives. Nothing has been run against a real ROS install.
